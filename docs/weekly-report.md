# 每周效果报告（给任何平台的 agent）

这份说明不依赖 Claude Code：只要能读写本机文件，Claude Code 的定时任务、Codex、Cursor、pi、opencode 都可以照着写周报。
auto-router 的配置和做法以后再改，这份说明也不用跟着改：插件自己把数据、配置版本和最近的改动写进报告文件。

## 怎么设定时任务

不用自己写提示词。插件每次写报告时会把这份说明复制成 `<数据目录>/report/weekly-report-guide.md`（位置固定，插件升级换了安装目录也不受影响），提示词只要让 agent 读它：

1. 拿提示词：运行 `/auto-router weekly [周报目录]`，或在 `/auto-router` 的 Claude 页点“📋 复制周报定时任务的提示词”（快速开始、数据与报告两处都有）。周报目录不写时是 `<数据目录>/weekly`。生成的提示词已经填好本机的完整路径，大致是：

   ```
   按 <数据目录>/report/weekly-report-guide.md 写本周的 auto-router 效果报告（只读这份说明，照它做）。
   报告文件：<数据目录>/report/latest.md
   周报写到：<周报目录>
   不开子代理，不超过 15 次工具调用。
   ```

2. 设成每周跑一次：
   - Claude Code 桌面版：侧栏「定时任务」→ 新建，粘贴提示词，选每周一次；
   - Claude Code 命令行：用系统定时器跑 `claude -p "<提示词>"`（Windows 用任务计划程序，macOS / Linux 用 cron）；
   - 其他 agent（Codex、Cursor、pi、opencode 等）：用它自己的定时功能，或同样用系统定时器调它的命令行，提示词不变。

改了数据目录以后重新复制一次提示词即可。

## 输入

`<数据目录>` 是 auto-router 配置里的 `dataDir`（空的话是 `~/.claude/auto-router`）；`/auto-router path` 会显示完整路径。

| 文件 | 内容 |
|---|---|
| `<数据目录>/report/latest.md` | 插件每小时最多更新一次的效果报告：最近 7 天和 28 天的对照实验结论（只比当前配置版本）、按配置版本的参考数据、按类别的轮数和纠正、整体汇总、CHANGELOG 最近两个版本的条目标题 |
| `<数据目录>/report/latest.json` | 同样的数据，给脚本用；`generatedAt` 是生成时间（毫秒），`configVersion` 是当前配置版本，`settings` 是当时的切换和省额度配置 |
| 周报目录里上一份 `auto-router-report-*.md` | 上周的结论，用来对比 |

只读这几个文件，不读原始日志（`<数据目录>/log/`），不读会话记录。

## 步骤

1. 读 `latest.md`。看文件头的生成时间：超过 3 天没更新，在周报开头写明“数据截至 <时间>”（多半是这期间没开 Claude Code）。
2. 读上一份周报（没有就跳过）。
3. 写 `<周报目录>/auto-router-report-<YYYY-MM-DD>.md`，不超过 80 行，结构如下。

## 周报结构

1. **一句话结论**：整体在省、在亏，还是看不出来。
2. **本周改了什么**：`latest.md` 末尾“最近的改动”里，上一份周报之后的条目，一行一条；没有就写“无”。当前配置版本和上周不同时写明：“配置版本从 A 换成 B，对照实验从新版本重新攒样本”。
3. **各项效果**，每项标“数据支持 / 样本不足 / 推测”：
   - 模型切换：对照实验【模型切换】一段的结论原样引用，再写每会话花费、纠正率；整体汇总里的 `netUsd`（换小模型少花 − 缓存重写 − 分类）；分类失败的轮次占比。报告里有“冷点”“本地规则”两行时一并写出：冷点占比、冷点上换模型和冷点之间升档的次数、规则和小模型分类的一致率（低于七成时建议调规则）。`switchAt` 是 `cold` 时，冷点上换模型不算缓存重写的钱，`switchUsd` 只来自冷点之间的升档。
   - 省额度：【省额度】一段的结论；拦截次数和再请求比例；两组平均上下文。
   - 外派：任务数、按角色派的成功率（`pi.routedOk / pi.routed`）、各模型任务数；报告里有“外派返工”一段时，写出返工多的模型（`piRedo`）和是否已被排到角色链后面。
   - 编码类：按类别表里编码类 ≥20 轮且纠正率 >15% 时，建议把编码改回 Opus，否则写“继续观察”。
   - 花费构成：报告里“花费构成”一段（`latest.json` 的 `overall.costSplit`）：读缓存、写缓存、输出各占多少，每轮平均上下文；写缓存里隔太久缓存过期的重建花了多少。这是额度的大头，换模型只影响单价。
4. **和上周比**：上面几项的变化方向。
5. **1~3 条建议**：写明改哪个配置项、预期效果；没有数据支持的标“推测”。花费构成里读写缓存占八成以上、每轮平均上下文超过 15 万时，优先建议使用习惯（换任务开新会话、歇久了回来先 `/compact`），而不是换模型；隔太久重建的花费明显时同样提一句。

## 规则

- 结论以报告里“对照实验”的判断为准：每组不到 15 个会话就是“样本不足”，别自己从几个数字下结论。
- “按配置版本”一段只作参考：旧版本的做法不同，不拿它和当前版本的结论混在一起。
- 只写周报：不改 auto-router 的配置、代码和其他文件。
- 不建议调低推理强度、自动压缩阈值，不建议硬截断工具输出；建议换更便宜的模型必须有纠正率数据支持。
- 用 3~5 句话收尾：结论、最关键的数字、最重要的建议、周报路径。

## 可选：全机 token 趋势

装了 Python 时，可以在周报目录里加跑 `scripts/token_report.py --days 7 --compare <基线.json> --save week-<日期>.json`（设置 `PYTHONIOENCODING=utf-8`），把平均每次调用的输入、第一轮输入、最大上下文和基线、上周比较，写成周报里单独一节。这一步读的是 Claude Code 的会话记录，别的平台没有就跳过。
