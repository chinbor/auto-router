# 优化方案与待办

记录于 2026-10-30（0.2.2 之后）。先定方案，按优先级逐条做；做完一条就勾掉，并在 CHANGELOG 写一条。

背景：0.2.2 把编码类默认从 Opus 改成了 Sonnet，依据是外部的选型调研，需要用自己的数据确认。下面前三条就是为了让这个判断（以及以后的同类判断）能用数据做出来。

## 待办

### P1：让结论更快、更可信

- [ ] **1. 对照报告按类别拆开**
  - 现状：`stats.ts` 的 `sessionStats` / `experimentReport` 只按会话和组汇总，`summarize` 只按组和模型计数，看不出某一类问题的纠正率。
  - 做法：
    - 新增 `categoryStats(records, from)`：按 `cat` 统计每类的轮数、花费、纠正次数和纠正率，再按组（`ra`）分开。
    - **纠正要记在上一轮的类别上**：`fix` 标在用户纠正的那一轮，被纠正的其实是上一轮的回答，所以要按会话顺序把 `fix` 归到前一轮的 `cat` 和 `model`。
    - `/auto-router eval` 报告和面板“效果”页各加一张按类别的表；样本少于 20 轮的类别标“样本不足”，不下结论。
  - 验收：
    - 测试覆盖纠正归到上一轮；
    - 用真实日志跑一次，能看到“编码”在切换组和不切换组的纠正率。

- [ ] **2. 映射自己提建议**
  - 依赖第 1 条。
  - 做法：
    - 某一类最近 N 轮（默认 30）的纠正率超过阈值（默认 15%），且当前不是最高档，就建议升一档；
    - 纠正率低于阈值的三分之一、且当前在 Opus，就建议降一档；
    - 建议显示在面板“Claude 模型”页的该类别旁边，点“应用”才改配置，不自动改。状态行不显示，避免打扰。
  - 配置：`claude.suggest`，包含 `enabled`、`minTurns`、`fixRate`。
  - 验收：
    - 纯函数 `suggestMappings(stats, cfg)` 有测试，覆盖升档、降档、样本不足、已是最高档这几种情况；
    - 面板点“应用”后配置文件对应类别的 `model` 改变。

- [ ] **3. 简单的问题本地直接分类**
  - 背景：7 天额度超过约 80% 后插件调 classify 会报 429，只能走 fork，而 fork 花的是主对话额度。
  - 做法：在 `classify.ts` 调模型之前加一层规则，命中就直接返回，日志记 `via: 'rule'`：
    - 问候、致谢、确认（“你好”“谢谢”“好的”“ok”“继续”），不超过约 12 个字，判为“闲聊/简答”；
    - 以 `!`、`/` 开头的命令不分类；
    - 规则只判最有把握的几类，拿不准的照常交给模型。
  - 配置：`claude.ruleClassify`，默认开，可关掉做对比。
  - 验收：
    - 测试覆盖命中、不命中、长句含“谢谢”但不该命中这几种情况；
    - 日志里能统计 `via: 'rule'` 的占比。

### P2：少花冤枉钱

- [ ] **4. 换模型带来的缓存重建成本**
  - 背景：换模型后，这个会话已有的提示缓存就用不上了，下一轮要整段重写。上下文越大，降档省下的越可能抵不上这笔成本。
  - 做法：
    - 用日志里 `switched` 轮的 `cw` 和换模型前后每轮花费，算出降档的回本轮数；
    - 把 `keepAboveTokens` 从固定的 15 万改成按回本算：预计这段对话剩下的轮数回不了本，就不降档。
  - 先出一份分析报告，确认值得做再改代码。

- [ ] **5. 按实际表现给 pi 模型排序**
  - 做法：
    - pi 记录里补上你最后保留了多少改动（下次 `git diff` 时对比）；
    - 按模型统计成功率、耗时和保留率，每个角色的尝试顺序按这些数据调整；
    - 手写的顺序作为初始值，样本够了才调。
  - 面板“pi 模型”页显示每个模型的这几项数据。

### P3：方便别人用

- [ ] **6. 首次配置自动探测**
  - 做法：首次运行 `pi --list-models`，把认识的模型按名字预填进分档（强、中、轻），用户只需确认；不认识的模型放进“不用”。

- [ ] **7. 节假日自动拉取**
  - 做法：从公开的节假日日历（如 holiday-cn 的 JSON）拉当年数据，缓存在本地，失败时沿用手写的配置。

## 怎么推进

- 第 1 条最先做：没有按类别的数据，0.2.2 的调整没法验证，第 2 条也做不了。
- 第 2、3 条互不依赖，可以一起做。
- 第 4 条先做分析，有结论再决定要不要改。
- 每条都要先写测试，`claude plugin validate .` 和 `claude plugin test .` 通过后再提交。
