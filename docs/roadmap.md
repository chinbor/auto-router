# 优化方案与待办

记录于 2026-10-30（0.2.2 之后）。先定方案，按优先级逐条做；做完一条就勾掉，并在 CHANGELOG 写一条。

背景：0.2.2 把编码类默认从 Opus 改成了 Sonnet，依据是外部的选型调研，需要用自己的数据确认。下面前三条就是为了让这个判断（以及以后的同类判断）能用数据做出来。

## 待办

### P1：让结论更快、更可信

- [~] **1. 对照报告按类别拆开**（0.2.3 已在 `router_config report` 里出表；面板“效果”页和 `/auto-router eval` 还没加）
  - 现状：`stats.ts` 的 `sessionStats` / `experimentReport` 只按会话和组汇总，`summarize` 只按组和模型计数，看不出某一类问题的纠正率。
  - 做法：
    - 新增 `categoryStats(records, from)`：按 `cat` 统计每类的轮数、花费、纠正次数和纠正率，再按组（`ra`）分开。
    - **纠正要记在上一轮的类别上**：`fix` 标在用户纠正的那一轮，被纠正的其实是上一轮的回答，所以要按会话顺序把 `fix` 归到前一轮的 `cat` 和 `model`。
    - `/auto-router eval` 报告和面板“效果”页各加一张按类别的表；样本少于 20 轮的类别标“样本不足”，不下结论。
  - 验收：
    - 测试覆盖纠正归到上一轮；
    - 用真实日志跑一次，能看到“编码”在切换组和不切换组的纠正率。

- [ ] **2. 映射自己提建议**
  - 依赖第 1 条。
  - 做法：
    - 某一类最近 N 轮（默认 30）的纠正率超过阈值（默认 15%），且当前不是最高档，就建议升一档；
    - 纠正率低于阈值的三分之一、且当前在 Opus，就建议降一档；
    - 建议显示在面板“Claude 模型”页的该类别旁边，点“应用”才改配置，不自动改。状态行不显示，避免打扰。
  - 配置：`claude.suggest`，包含 `enabled`、`minTurns`、`fixRate`。
  - 验收：
    - 纯函数 `suggestMappings(stats, cfg)` 有测试，覆盖升档、降档、样本不足、已是最高档这几种情况；
    - 面板点“应用”后配置文件对应类别的 `model` 改变。

- [ ] **3. 有把握的消息先用本地规则分类**
  - 已有（0.4）：`rules.ts` 的关键词规则在冷点上小模型被限流或超时时兜底（日志 `via: 'rule'`），冷点之间每轮也跑，用来当场升档；小模型分出来时也记下规则判的类别（`rc`），报告“本地规则 和小模型分类一致 N%”。限流后有冷却，冷却期内不再请求小模型；`forkFallback` 默认关，不会因为限流去花主对话额度。
  - 背景：插件自己的 classify 请求常被 429 限流（主对话不受影响）。规则能判出约四成消息，剩下的在限流时只能保持当前模型。
  - 要做：`ruleHit` 判为 strong 的消息（问候、致谢、“继续”这类短句等）跳过小模型直接用规则结果，省掉最多 4 秒的等待和一次可能被限流的请求。这解决不了另外六成分不出来的问题。
  - 前提：报告里规则一致率攒到几十轮、并且在八成以上再做；低了先调规则。
  - 配置：`claude.ruleFirst`，默认开，可关掉做对比。
  - 验收：
    - 测试覆盖：strong 命中不调 classify；弱命中照常先问小模型；长句里含“谢谢”不算 strong；
    - 日志里 `via: 'rule'` 且没有 `cf` 的就是规则先判的，报告能单独数出来。

### P2：少花冤枉钱

- [ ] **4. 换模型带来的缓存重建成本**
  - 背景：换模型后，这个会话已有的提示缓存就用不上了，下一轮要整段重写。上下文越大，降档省下的越可能抵不上这笔成本。
  - 做法：
    - 用日志里 `switched` 轮的 `cw` 和换模型前后每轮花费，算出降档的回本轮数；
    - 把 `keepAboveTokens` 从固定的 15 万改成按回本算：预计这段对话剩下的轮数回不了本，就不降档。
  - 先出一份分析报告，确认值得做再改代码。

- [ ] **5. 按实际表现给 pi 模型排序**
  - 做法：
    - pi 记录里补上你最后保留了多少改动（下次 `git diff` 时对比）；
    - 按模型统计成功率、耗时和保留率，每个角色的尝试顺序按这些数据调整；
    - 手写的顺序作为初始值，样本够了才调。
  - 面板“外派模型”页显示每个模型的这几项数据。
  - 0.3.0 进展：opencode 免费模型接进来后，记录多了 `ch`（通道）字段；`scripts/bench_models.py` 用固定任务给免费模型打分，档位和 `pi.strengths` 先按这份实测定。真实派活的成功率、保留率还要攒数据，到时与基准分对照，基准分只作初始值。
  - 0.5.0：opencode 通道去掉，免费模型经 magpie 在 pi 里跑，新记录不再写 `ch`；`bench_models.py` 改成经 pi 跑，打分不变。

### P3：方便别人用

- [ ] **6. 首次配置自动探测**
  - 做法：首次运行 `pi --list-models`，把认识的模型按名字预填进分档（强、中、轻），用户只需确认；不认识的模型放进“不用”。
  - 0.3.0 进展：opencode 一侧已经会探测（打开面板时跑 `opencode models opencode`，没装时显示安装提示，下架的模型划掉并在派活时跳过）；pi 一侧的预填分档还没做。
  - 0.5.0：只剩 pi 一个清单，`pi --list-models` 里没有了的模型派活时跳过；新上的免费模型（magpie/opencode-zen-free/ 下）按 `pi.freeModels` 自动算免费，但档位仍要手动标。
  - 新出的免费模型（如官方文档里有、本机还没列出的 nemotron-3-ultra-free、jev-1.13-free）不会自动加档位，要手动标或跑一次基准。
