# 交出去之前

## 先判断要不要交

- 需要判断、取舍、写提示词或定参数的，自己做。
- 活小（几步就完）自己做：子代理有启动开销，受控测试里小活交出去反而更费。
- 当前主会话就是 Sonnet / Haiku 时，交给 Sonnet 子代理省不了多少，自己做。
- 只有做完后还要在本会话继续长时间工作（主会话上下文值得保住）时，才交出去。

## 交给谁

| 活 | 交给 | 占谁的额度 |
|---|---|---|
| 读不到约 3 万 token 的材料 | 自己读 | — |
| 读 3 万–20 万 token；要上网、要 MCP 工具，或含不该发给第三方的私密内容 | `auto-router:scout` | Claude（Sonnet） |
| 读超过约 20 万 token，或 7 天额度已用过阈值（默认 70%），材料都在本机 | `pi_dispatch` role=longctx | 先试 opencode 免费的 DeepSeek-v4.1，再试 pi 的 DeepSeek 按量（高峰时段排队） |
| 写死了每一步的批量机械执行 | `pi_dispatch` role=bulk / code（要 git 干净），都不可用时 `auto-router:executor` | pi 订阅或 opencode 免费；executor 占 Claude |

`saver.bigRead` 设成 scout 或 pi 时，大量阅读固定交给那一边。

## executor / pi 的任务清单模板

executor 和 pi 都看不到本会话，只照清单做；没写到的一律停下交回。

```markdown
# 任务清单：<一句话标题>

## 目标
<要达到的结果，一两句话>

## 前提
- 工作目录：<绝对路径>
- 已有的输入：<文件、环境变量、要先满足的条件>
- 不要碰：<不许改的文件或目录>

## 步骤
1. <具体命令，或“把 X 文件第几行的 A 改成 B”这种写死的改法>
2. ...
（每步只做一件事；参数、提示词、文件名都写死，不留“合适的”“看情况”这类词）

## 验收标准
- [ ] <可以客观检查的条件，例如“目录下有 30 个 .md，每个都含 `tags:` 字段”>

## 遇到这些情况要停下
- 清单没写到的情况、某步有两种以上理解
- 预料外的报错：<列出允许自行处理的报错及处理方式，没列的都停>
- <任务特有的停止条件>

## 汇报格式（40 行以内）
状态 / 每步结果 / 产出路径 / 验收自查 / 问题或停下原因
```

scout 不用清单，给它：要回答的问题、要覆盖的每一项、从哪里找起。

## 验收

按清单里的标准检查产出，不重读执行过程；不合格就重做或自己接手。pi 改过的文件用 `git diff` 审阅后再决定保留。
